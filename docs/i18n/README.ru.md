<p align="center"><sub>Интерфейс с демонстрационными данными. Есть мобильная версия, светлая и тёмная темы.</sub></p>

Render Node превращает Linux-машину или GPU Pod в личное рабочее место для
рендера Blender. Загрузите сцену, выберите версию Blender и ресурсы, поставьте
задачу в очередь, затем следите за прогрессом и скачивайте результаты на той же
странице.

Проект рассчитан на **одного оператора и его собственные доверенные сцены**.
Задачи выполняются в порядке FIFO: одновременно активна одна логическая задача,
которая может использовать несколько GPU.

## Возможности

| | Что можно делать |
|---|---|
| **От сцены к задаче** | Загружать `.blend` или ZIP, выбирать движок и диапазон кадров, редактировать задачу и заменять сцену до первого запуска. |
| **Управление очередью** | Запускать, отменять, повторять попытку или создавать редактируемую копию для нового рендера. История задач хранится в SQLite. |
| **Рендер на GPU** | Использовать CUDA или OptiX, выбирать GPU и переключаться между распределением кадров и общим процессом рендера. Доступен и рендер на CPU. |
| **Наблюдение за рендером** | Видеть общий прогресс и прогресс workers, затраченное время, оценку оставшегося времени, превью и логи Blender через WebSocket. |
| **Результаты** | Просматривать кадры, скачивать оригиналы, ZIP с кадрами и логи. История задач и метаданные артефактов сохраняются после перезапуска backend. |
| **Версии и доступ** | Скачивать, устанавливать и явно активировать версии Blender. Подключать другие браузеры по одноразовым приглашениям. |

### Два режима GPU

| Режим | Как работает | Для чего подходит |
|---|---|---|
| **Frame per GPU** | Каждая выбранная GPU запускает свой процесс Blender и рендерит назначенные кадры с учётом `frame_step` сцены. | Параллельный рендер кадров анимации. |
| **All GPUs per frame** | Один процесс Blender использует все выбранные GPU для текущего кадра. | Работа нескольких GPU над одним кадром. |

Для CUDA/OptiX с двумя и более GPU по умолчанию выбран **Frame per GPU**.
CPU и одна GPU используют режим общего процесса. Рендер на нескольких GPU
остаётся одной задачей в очереди.

## Быстрый старт

Для локальной разработки на Linux нужны **Python 3.13**, **uv**,
**Node.js 22.12+** и **make**. Для запуска интерфейса Blender не требуется.

```bash
git clone https://github.com/NikkZhur/Render-Node.git
cd Render-Node

(cd backend && uv sync --frozen)
npm --prefix frontend ci

export RENDER_NODE_WORKSPACE="$HOME/render-node-data"
export RENDER_NODE_DATABASE_URL="sqlite+aiosqlite:///$RENDER_NODE_WORKSPACE/database/render-node.sqlite3"

make dev
```

Откройте **[localhost:5173](http://localhost:5173)**. `make dev` применяет
миграции БД, запускает API на порту `8000`, ждёт готовности и запускает Vite
на порту `5173`. `Ctrl+C` останавливает оба сервиса. Данные остаются в указанном
рабочем каталоге; в новом терминале задайте обе переменные окружения снова.

1. Откройте **Blender versions**, скачайте, установите и активируйте версию.
2. Создайте задачу и загрузите `.blend` или ZIP со сценой и её ресурсами.
3. Дождитесь анализа: движок, кадры и устройства заполнятся автоматически.
   При необходимости измените настройки и запустите рендер.
4. Следите за превью и логами; скачайте готовые кадры в **Artifacts**.

Первый браузер, открывший свободный узел, получает доступ. Для другого браузера
используйте **Pair another device**. Перезапуск backend сбрасывает браузерные
сессии, но сохраняет задачи и файлы. Сервер разработки опирается на локальные
ограничения ресурсов и предназначен для доверенного окружения разработки.

Для просмотра только интерфейса запустите `npm --prefix frontend run dev:mock`
и откройте тот же порт. Этот режим использует демонстрационные данные и не
рендерит сцены.

Раздельный запуск сервисов, настройки, проверки и сценарии Playwright описаны
в [руководстве разработчика](../development.md).

## Развёртывание

Установщик рассчитан на **Ubuntu 22.04/24.04 x86_64 GPU Pod** с работающим
`nvidia-smi`. Запустите его от root и откройте порт **8080** через HTTPS-прокси
провайдера:

```bash
curl -fsSL https://raw.githubusercontent.com/NikkZhur/Render-Node/master/install.sh | bash
```

> [!NOTE]
> Установщику нужен опубликованный стабильный пакет GitHub Release. Стабильных
> релизов пока нет; до публикации используйте запуск из исходников выше.
> См. [релизы](https://github.com/NikkZhur/Render-Node/releases) и
> [инструкцию публикации](../../deploy/README.md#publication).

Установщик готовит новую версию до переключения и выполняет откат, если проверка
готовности не проходит. В репозитории также есть рецепт Docker-образа для
платформ, запускающих образ напрямую. Оба варианта требуют доступного для записи
делегированного поддерева **cgroup v2** для production-рендера: готовность HTTP
сама по себе не означает, что рендер доступен.

[Установка, обновление, откат, pairing и резервные копии →](../../deploy/README.md)

## Устройство проекта

**React + Vite** · **TanStack Query + Zustand** · **FastAPI** ·
**SQLite + SQLAlchemy + Alembic** · **Процессы Blender + NVIDIA NVML**

```text
frontend/   React-интерфейс, API-клиент и браузерные проверки
backend/    FastAPI, очередь, запуск Blender, хранение данных и тесты
deploy/     Скрипты окружения и руководство по развёртыванию
scripts/    Запуск разработки, управление узлом и упаковка релиза
docs/       Архитектура, разработка, состояние проекта и переводы
```

Один узел, один процесс API, хранение в SQLite. Внешний сервис очереди или БД
не требуется. Границы модулей и REST/WebSocket-контракты описаны
в [архитектуре](../architecture.md).
